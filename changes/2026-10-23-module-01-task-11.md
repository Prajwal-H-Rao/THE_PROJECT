## Why the trace already existed

The gateway built the trace edge in task 4. `src/lib/trace.ts` reads the W3C
`traceparent` header, validates the 32-hex trace id, and generates a fresh
context otherwise. `src/proxy.ts` forwards the header. The envelope of task 13
carries the `correlation_id` field of spec:755. Task 11 connects those pieces
and makes the chain proof-carrying.

## Files

- New `queues/traceparent.mjs`: the runner-local W3C parse and synthesis. The
  runner image copies only `queues/`, so a gateway import would dangle.
- `queues/envelope.mjs`: `buildEnvelope` gains an optional `correlationId`
  argument. A caller may pin it; the default stays a random UUID.
