## Honest claims

- The migration tooling is a standalone runner (`pg` only, no ORM) that replays from zero. The db/init files remain the source of truth for the Compose stack; the migration files are the canonical source for the tooling.
- Audit hash chaining is tamper evidence (spec:907), not immutability. The `verify_hash_chain` function detects edits.
- Check constraint `audit_log_succeeded_requires_evidence` enforces spec:141: `execution_status = 'succeeded'` requires `verification_type <> 'none'`.
- Append-only enforced by `REVOKE UPDATE, DELETE ON audit_log FROM audit_activity_service`.
- Object-storage pointers (`raw_ref`, `receipt_ref`, `itinerary_ref`, etc.) are TEXT fields; task 13 will wire deletion propagation.
- pgvector column `content_vector VECTOR(1536)` added in notes schema now (task 11) to avoid privileged migration later.
