## Honest claims

- OIDC flow uses PKCE (S256) with per-request state and code verifier; state stored server-side with 10-min TTL, consume-once
- Session tokens are HMAC-SHA256 signed, base64url encoded, versioned (v1); CSRF token bound to session
- TOTP uses otplib (RFC 6238); backup codes are hashed with HMAC-SHA256; used backup codes are removed
- Session tokens carry `sid` (session ID), `sub` (user ID), `tenant`, `channel`, `csrf`; expiry configurable
- Session validation checks token signature, expiry, session existence, revocation status, and CSRF match
- Account linking uses provider user ID as unique key; prevents duplicate links
- TOTP backup codes are single-use; hashed with salt; removed on use
